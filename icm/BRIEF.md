# BRIEF — Design Decisions for v0.1.0

**Artifact type:** ICM Brief (approved design decisions derived from SPEC.md)
**Status:** ACTIVE
**Date:** 2026-08-09

## Decision log

**B1 — Agent file format.** The agent file uses YAML frontmatter (`name`, `description`) followed by the full operational specification, making it drop-in compatible with Claude Code custom agents (`.claude/agents/`) while remaining a readable standalone document for other environments.

**B2 — Repository structure.** Extend the proposed structure with three additions, each with a stated reason:
- `icm/` — the Spec/Brief/Task artifacts for the package itself. An ICM-native standard should demonstrate ICM on its own construction.
- `tests/validate_package.py` — a mechanical validator. Behavioral tests require a human or model runner; the validator gives one check that runs deterministically, and models the eventual shift from trusted-prompt rules to enforced rules.
- `PROVENANCE.md` at root plus `docs/self-review.md` — provenance and self-critique are release artifacts, not buried notes.

**B3 — Authority model.** The agent's authority is defined positively (what it may do) and negatively (what it may never do), with the negative list controlling in any conflict. Status vocabulary is closed: originally the four statuses in SPEC AC2 *(historical — AC2 superseded by AC9; the current closed vocabulary is defined in the v0.2 addendum below)*.

**B4 — Artifact discovery order.** The agent looks for governing context in this order: explicit task-provided artifacts → CONTEXT.md → decision records → PRD/spec files → configuration/governance files. Missing required context is a STOP, not a guess.

**B5 — Tone.** Operational language throughout. Imperatives, tables, and checklists. No persona traits, no experience claims, no motivational framing.

**B6 — Test design.** Each behavioral test targets one failure mode from the problem statement. PASS criteria are observable behaviors (stopped, reported, asked, refrained), never subjective quality scores.

**B7 — Comparison framework.** Eight dimensions matching the brief, scored on a three-level ordinal scale (Compliant / Partial / Violated) per dimension per run — ordinal levels are observable; numeric scores would be manufactured precision.

**B8 — Versioning.** v0.1.0, semantic versioning, CHANGELOG in Keep-a-Changelog style.

**B9 — Honest limitations.** README and self-review state plainly that prompt-level rules are not mechanically enforced and can fail; the package claims to *reduce*, not eliminate, scope drift.

# v0.2 / v0.2.1 Addendum — Hardening Decisions (2026-08-09)

**B10 — Gate placement.** The deterministic scope gate lives in `tests/` alongside the package validator rather than a new top-level directory: minimal structural change, and both are deterministic checking machinery.

**B11 — Dependency-free gate.** The gate parses its task-YAML subset with a built-in mini-parser instead of requiring PyYAML, so it runs anywhere Python runs.

**B12 — Authorization semantics (corrected v0.2.1).** `allowed_paths` is necessary for every change; `authorized_protected_paths` is an additional requirement for protected paths and never substitutes for allowance. Touching a protected artifact requires the path in both lists. An authorized-but-not-allowed protected change fails as a scope violation (exit 1), because the authorization rule is satisfied and the scope rule is not.

**B13 — No self-authorized mechanical scope.** When the gate is required, `allowed_paths` must come from the governing task artifact; the agent never writes, widens, or infers the declarations. The gate enforces this half mechanically by refusing to run (exit 3) without declared `allowed_paths`.

**B14 — Addendum-over-rewrite.** Versioned governing artifacts (SPEC, BRIEF, TASK, self-review) are reconciled by dated addenda plus historical labels on superseded statements, never by silently rewriting the original record.

**B15 — v0.2.1 --base completeness.** In `--base` mode the gate unions `git diff` output with untracked files (`git ls-files --others --exclude-standard`), since git diff reports tracked files only and an untracked file must not escape the gate.

**B16 — Single source of truth for derived facts (v0.2.7).** A fact stored twice drifts; the scenario count drifted three times before this rule. Living documents (README) may not carry numeric copies of facts owned elsewhere; they describe and point to the source. The validator's role inverts accordingly: it checks the source's own integrity (contiguous 1..N numbering, a one-way floor ratchet that fires on deletion and never on growth) and bans reintroduction of the copied number. Design constraint honored: no check may fire predictably on the author's known-intermediate state, because routine failures train alarm fatigue — the same operator-trust concern that motivated the F1 exit-code fix.

**B17 — The authorization is part of the audited surface (2026-08-14).** B13 banned self-authorized scope but enforced only its weaker half: the gate refused to run with no `allowed_paths`, and trusted whatever `allowed_paths` it was handed. Where task files live in the repository — the arrangement this package's own examples encourage — the declarations are agent-writable, so the gate's central claim ("it does not trust the model's description of what it changed") was defeated by editing the description. Decision: the gate checks the task file's own integrity before evaluating scope, and on any change to an in-repo task file returns a distinct exit 4 that withholds a scope verdict entirely rather than reporting one computed from untrusted declarations. A distinct code, not a reuse of exit 2, because the remediation differs in kind: exit 2 means "revert that file," exit 4 means "this audit did not happen." Configurations where the check cannot run (task file outside the repo, `task_path` not supplied) announce that on PASS, per B9's honest-limitations rule — an unperformed check must never read as a passed one.

**B18 — Unrunnable is a third outcome (2026-08-14).** A check the environment cannot execute is neither passed nor failed, and forcing it into either is a defect. Reporting it as a failure makes an entire platform's run end red for a reason unrelated to the code, which trains the reader to discount red output — the alarm-fatigue concern B16 already names. Reporting it as a pass claims a check that never happened, which B9 forbids. Decision: a suite reports skipped as its own outcome, names the scenario and the reason in its output, and still exits 0 when nothing actually misbehaved. Detection tests the capability, never the platform name: the first NTFS attempt probed only whether the file was created, and MSYS silently substitutes U+F022 for `"`, so the probe succeeded while git and Python saw a different name. A capability probe also covers the exFAT and network-share cases a `uname` check would miss.

**B19 — Fixtures ship; the answer key does not (2026-08-14).** `test-cases.md` described each repository state and left the building to the tester. A scenario's difficulty lives in the fixture rather than in the paragraph describing it, so results from separately built fixtures cannot be pooled, and the recorded runs were unreproducible because their throwaway repositories no longer existed. Decision: the fixtures are committed and built by a script, so two people running one scenario run the same scenario. Each scenario's prompt file carries the exact wording and the post-run checks, and is deliberately excluded from the built fixture — it names the trap, so inside the repository it would function as an answer key. Corollary, learned from this project's own first T8 fixture: a fixture can quietly stop testing what it claims, so the suite is re-verified mechanically rather than assumed intact, including an explicit assertion that T8 still exposes no sanctioned route to the data the scenario depends on being unreachable.

**B20 — The agent may not write its own decision record (2026-08-14).** Extends B17 from declarations to evidence. A durable per-task log is worth having: the Completion Report holds the reasoning, what was deliberately left alone, and the real check results, and all of it currently dies with the transcript. But a log the agent writes is the audited party writing the audit, and it must live somewhere — outside `allowed_paths` it fails every run, inside it grants a file the agent may always write to. Decision: any per-run log is written by the harness from the gate's own verdict, never by the agent. Human decision records (`decisions/approved/`) remain human-written and hook-protected. This log is distinct from this file: BRIEF records why the package is built as it is, a run log records what happened on a given run, and B16 forbids merging the two.

**B21 — This repository's own agent rules are not shipped (2026-08-14).** A `CLAUDE.md` in a repository auto-loads into any Claude Code session opened in a clone. This project's rules tell a session to read governing artifacts first and stay bounded, which is a partial restatement of the behavior `comparison-framework.md` exists to measure. A tester running the plain-agent condition inside a clone would therefore not be running a plain agent, inflating the baseline and understating the specification's effect. Decision: the file is kept locally and untracked, and the comparison framework warns that a self-supplied fixture may carry the same hazard. The rules that remain point at `icm/SPEC.md` rather than restating it, since a second copy of the governing principles is precisely what B16 forbids.

**B22 — A result carries its own provenance (2026-08-14).** Asking a tester to remember the model, the condition, and the gate result is asking at the moment they are least likely to comply: after the run, when they believe they are finished. Worse, the gate result would then be their summary of what happened rather than the gate's own output — the substitution this package exists to refuse, reintroduced at the reporting step. Decision: the mechanical fields are produced by running the gate and reading the diff, never typed; the two fields no tool can read out of a transcript are left explicitly blank rather than guessed; and model and condition are required arguments rather than defaulted values, since a result missing either cannot be compared with anything and a default would produce one silently. Results are kept as files carrying the package version and commit that built their fixture, because a result that cannot be traced to a fixture version cannot be rechecked later — the defect that left this project's own 144 recorded runs unreproducible.

**B23 — Adoption is a supported path, not an exercise (2026-08-14).** The package's install instructions covered the agent definition and left the enforcement machinery to seven manual steps, four of them undocumented — copying `hooks/` and `tests/scope_gate.py` while preserving their relative layout, rewriting `protected-paths.txt` for the target project, merging the settings snippet, restarting the session. A control nobody installs is not a control. Decision: `install.py` performs the mechanical steps and states plainly the three it cannot guess. Installed files land in `.claude/` and a single removable `.icm/` directory, never the project root, because the previous instructions would have created `hooks/` and `tests/` directories in projects that already have a `tests/` of their own. Existing hook configuration is merged rather than replaced. The protected-paths list is generated from the target project's own governing files rather than shipped as a copy of this package's, so it names paths that exist there; `tasks/` is written unconditionally, since the scan runs before the installer creates it and omitting it would ship every new installation with the F13 hole open. The hooks resolve the gate across both layouts rather than being rewritten at install time, so one set of files works here and there.

**B24 — Prevention and audit are complementary, not alternatives (2026-08-14).** The two hooks were asymmetric: the standing protected-path list was enforced before a write, while per-task `allowed_paths` was audited only at handoff. An agent could therefore spend a session editing files it had no authorization to touch and be told at the end, which satisfies "the violation was reported" but not "the work was kept in bounds". Decision: the PreToolUse hook also enforces the active task's `allowed_paths`, denying the write in the moment, with editing the task file itself denied as self-authorization at a precedence mirroring the gate's exit 4 > 2 > 1. The Stop hook is not made redundant by this and is kept: a PreToolUse hook sees only Write/Edit tool calls, while the gate audits the real Git diff, so anything reaching the filesystem another way is invisible to prevention and visible to the audit. Neither alone is sufficient. The new check fails open on an unreadable task file, consistent with this hook's existing posture (B9's honesty rule applied to degradation: a control that stops working must say so rather than silently blocking everything or silently allowing everything), and is inert unless `ICM_TASK_FILE` is set, so installing the hooks cannot break sessions that do not opt in.
